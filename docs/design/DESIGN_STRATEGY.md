# Estrategia de diseño

## Objetivo

Content Publisher debe permitir mucha variedad visual sin perder una identidad reconocible.

La solución no será una única plantilla ni un editor libre. Se utilizará una identidad central aplicada a una biblioteca extensible de arquetipos y variantes.

## Qué debe permanecer reconocible

La identidad final todavía no está diseñada, pero el sistema deberá reservar espacio para elementos constantes:

1. firma visual;
2. nombre mostrado;
3. familia tipográfica;
4. paleta principal;
5. sistema de series o numeración;
6. uno o varios pequeños recursos gráficos recurrentes;
7. reglas de espaciado y jerarquía.

Estos elementos deben poder convivir con diseños muy diferentes.

## Qué puede variar

- distribución;
- fondo;
- densidad;
- tamaño del titular;
- posición de screenshots;
- uso de diagramas;
- cantidad de texto;
- proporción entre imagen y contenido;
- variantes claras u oscuras;
- paletas secundarias;
- número de páginas.

## Familias iniciales

### Editorial

Para ideas, opiniones, conceptos y titulares con fuerte peso tipográfico.

Posibles arquetipos:

- Bold Statement
- Minimal Editorial
- Number / Metric Hero

### Product / Screenshot

Para enseñar aplicaciones, pantallas, prototipos o resultados visuales.

Posibles arquetipos:

- Hero Screenshot
- Split Screenshot
- Annotated Screenshot
- Before / After

### Technical

Para explicar arquitectura, código, procesos y decisiones técnicas.

Posibles arquetipos:

- Architecture Flow
- Code Focus
- Process Steps

### Carousel

Para tutoriales, historias progresivas y casos de estudio.

Posibles arquetipos:

- Tutorial Sequence
- Case Study
- Checklist / Lessons

## Objetivo de V1

Implementar aproximadamente 12 arquetipos base capaces de producir unas 30–40 apariencias diferentes mediante variantes controladas.

## Regla de propiedad intelectual

Las referencias externas se utilizarán para estudiar patrones, composición, jerarquía y soluciones visuales. No se copiarán layouts, identidades, ilustraciones o recursos protegidos de forma literal.

Cada arquetipo implementado debe poder justificarse como una composición propia basada en principios generales de diseño.

## Criterios para aceptar un arquetipo

Un arquetipo entra en la biblioteca si:

- resuelve una necesidad editorial concreta;
- se distingue suficientemente de los ya existentes;
- funciona con contenido real, no solo con un mockup perfecto;
- admite variaciones sin romper la composición;
- mantiene legibilidad en móvil;
- puede renderizarse de manera determinista;
- respeta la identidad global.

## Próximo trabajo de diseño

Antes de definir colores o logotipo se realizará una investigación visual amplia. A partir de ella se elegirán tres direcciones de identidad visual claramente diferentes y se probarán sobre publicaciones reales.
