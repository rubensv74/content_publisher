# Direcciones iniciales de identidad visual

Estas tres direcciones son deliberadamente diferentes. No representan diseños cerrados ni una elección final. Su objetivo es evitar que la identidad se decida empezando por un color o un logotipo aislado.

La dirección definitiva deberá probarse con contenido real antes de aprobarse.

---

## Dirección A — Technical Editorial

### Idea

Una identidad sobria, contemporánea y editorial. El contenido técnico se presenta como conocimiento profesional, no como publicidad de software.

### Sensación

- precisa;
- limpia;
- adulta;
- muy legible;
- cercana a una revista de tecnología o producto.

### Recursos

- fondos principalmente claros o muy oscuros;
- tipografía sans serif con jerarquía fuerte;
- una línea o marcador fino recurrente;
- pequeñas etiquetas de dominio;
- números de serie discretos;
- screenshots sin marcos decorativos innecesarios;
- gráficos limpios.

### Firma

Pequeña marca tipográfica, por ejemplo una `R` o un símbolo geométrico acompañado del nombre de forma secundaria.

### Ventajas

- envejece bien;
- funciona con Power Platform, datos, arquitectura, Android o React;
- da protagonismo al contenido;
- permite mucha variedad.

### Riesgo

Puede resultar demasiado neutra si la microfirma, tipografía y acentos no tienen suficiente personalidad.

---

## Dirección B — Structured Signal

### Idea

La identidad se basa en un sistema de señalización: códigos, series, etiquetas, líneas y pequeños bloques de color. Recuerda a documentación de ingeniería bien diseñada, sin parecer un plano técnico.

### Sensación

- sistemática;
- reconocible;
- técnica;
- ordenada;
- propia.

### Recursos

- códigos como `BUILD / 014`, `DATA / 006`, `ARCH / 008`;
- módulos con pequeñas etiquetas;
- un color de señalización recurrente;
- geometría de esquinas y líneas;
- índices o coordenadas visuales sutiles;
- uso fuerte de retícula.

### Firma

La firma forma parte del propio sistema de señalización en lugar de aparecer como un logo tradicional.

Ejemplo conceptual:

`R / 2026 / BUILD-014`

### Ventajas

- puede convertirse en una seña muy reconocible;
- encaja especialmente bien con arquitectura, sistemas, datos y desarrollo;
- facilita construir series.

### Riesgo

Si se exageran códigos y líneas puede parecer excesivamente técnico o frío.

---

## Dirección C — Product Notebook

### Idea

Cada publicación se siente como una página de un cuaderno profesional de construcción: capturas, notas, pequeños marcadores, decisiones y conclusiones.

No imita un cuaderno manuscrito. El concepto es “documentar lo construido”.

### Sensación

- cercana;
- práctica;
- experimental;
- orientada a aprendizaje;
- menos corporativa.

### Recursos

- screenshots grandes;
- notas laterales breves;
- pequeños subrayados o callouts;
- etiquetas `problem`, `decision`, `result`, `lesson`;
- fondos naturales o neutros;
- mezcla de composición editorial y documentación de producto.

### Firma

Sello pequeño de autor, similar a una marca de revisión o aprobación, pero diseñado específicamente para la identidad.

### Ventajas

- conecta muy bien con publicaciones de “esto es lo que construí y aprendí”;
- diferencia el contenido de los carruseles corporativos típicos;
- permite enseñar proceso, no solo resultado.

### Riesgo

Debe evitarse caer en estética de post-it, papel roto o scrapbook, que se volvería decorativa y poco profesional.

---

# Recomendación preliminar

La dirección más prometedora no es usar una de las tres de forma pura, sino estudiar especialmente una combinación controlada de:

**Technical Editorial + Structured Signal**

con algunos recursos de Product Notebook para publicaciones de construcción.

Eso permitiría que la base sea sobria y duradera, mientras el sistema de series y señalización aporta una firma reconocible.

No se considera una decisión final. Antes deben generarse muestras reales de las tres direcciones y compararlas con el mismo contenido.

# Prueba propuesta

Utilizar exactamente tres historias para comparar las direcciones:

1. una publicación de Power Platform con screenshot;
2. una publicación de arquitectura con diagrama;
3. una publicación de datos con una métrica o gráfico.

Cada historia se compondrá en A, B y C. La identidad se elegirá comparando nueve piezas, no un logo aislado.
